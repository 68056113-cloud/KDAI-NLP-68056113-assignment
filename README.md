# การพัฒนาระบบ Contextual Retrieval (Authentic RAG) และเปรียบเทียบประสิทธิภาพ

**จัดทำโดย:** นายอธิพัชร์ ปฐพีวัฒนศิริ
**รหัสนักศึกษา:** 68056113
**วิชา:** Natural Language Processing (Assignment 4 Oct 2026)

โปรเจกต์นี้เป็นการศึกษาและพัฒนาต่อยอดระบบ **Authentic RAG (Contextual Retrieval)** ตามแนวทางของ Anthropic และโครงสร้างสถาปัตยกรรมฐานข้อมูล OpenSearch

---

## อธิบายความแตกต่างระหว่างระบบที่ (1) ต้นฉบับ และ (2) ปรับปรุงใหม่

(ต่างกันตรงไหน ดีขึ้นอย่างไร และเพราะเหตุใด?)

### 1. ด้านการทำ Chunking (การแบ่งส่วนเอกสาร)
* **ต่างกันตรงไหน:** ระบบที่ (1) ตัดแบ่งข้อความตามจำนวนตัวอักษรเป็นหลัก ส่วนระบบที่ (2) นำโมเดลตัดประโยคภาษาไทย (`pythainlp.tokenize.sent_tokenize`) มาจัดขอบเขตประโยคก่อนตัด
* **ดีขึ้นอย่างไร:** ลดปัญหาประโยคขาดครึ่ง ทำให้แต่ละ Chunk มีใจความสมบูรณ์ในตัวเองก่อนนำไปสร้าง Context กำกับ
* **เพราะเหตุใด:** ภาษาไทยไม่มีการเว้นวรรคระหว่างคำ การตัดด้วยความยาวตัวอักษรตรงๆ จะทำให้บริบทฉีกขาด ส่งผลให้ทั้งการทำ Contextual Embedding และการนับ Term Frequency ผิดเพี้ยน

### 2. ด้านการทำ Lexical Search & Inverted Index (BM25)
* **ต่างกันตรงไหน:** ระบบที่ (1) ใช้ `standard` analyzer ใน Inverted Index แต่ระบบที่ (2) เปลี่ยนมาใช้ `thai` analyzer พร้อมถ่วงน้ำหนักคะแนน (Field Boosting)
* **ดีขึ้นอย่างไร:** การค้นหาคำเฉพาะ (Exact Keyword) แม่นยำขึ้นอย่างมาก
* **เพราะเหตุใด:** OpenSearch ต้องพึ่งพา Analyzer ในการแยกข้อความออกเป็น Token เพื่อเก็บค่า TF และ DF หากใช้ `standard` analyzer ประโยคภาษาไทยทั้งบรรทัดจะถูกมองเป็น 1 คำ การเปลี่ยนเป็น `thai` analyzer จึงช่วยให้แยกคำลง Index ได้ถูกต้อง

### 3. ด้านการทำ Embedding
* **ต่างกันตรงไหน:** ระบบที่ (2) เปลี่ยนมาใช้โมเดล `BAAI/bge-m3` และบังคับทำ **L2 Normalization** (`normalize_embeddings=True`)
* **ดีขึ้นอย่างไร:** การค้นหาเชิงความหมาย (Contextualized Semantics) แม่นยำและเสถียรขึ้น
* **เพราะเหตุใด:** การทำ Normalization ให้เวกเตอร์มีความยาวเท่ากับ 1 จะทำให้การคำนวณ Cosine Similarity ลดรูปเหลือเพียง Inner Product ซึ่งช่วยตัดความเอนเอียงจากความยาวของข้อความทิ้งไป

### 4. ด้าน Search Algorithm & Scoring (Hybrid Fusion)
* **ต่างกันตรงไหน:** ระบบที่ (1) ดึงผลลัพธ์จาก Vector และ BM25 มารวมกันโดยตรง แต่ระบบที่ (2) ใช้อัลกอริทึม **Weighted Reciprocal Rank Fusion (Weighted RRF)** 
* **ดีขึ้นอย่างไร:** แก้ปัญหาความไม่สมดุลของคะแนน (Score Calibration) ระหว่าง 2 ระบบ
* **เพราะเหตุใด:** คะแนน Cosine Similarity มีค่าระหว่าง 0 ถึง 1 แต่คะแนน BM25 มีค่าตั้งแต่ 0 ถึงอนันต์ การนำคะแนนมาเทียบกันตรงๆ จะทำให้ฝั่ง BM25 กลบฝั่ง Vector การใช้ RRF จึงเปลี่ยนมาคิดคะแนนจาก "ลำดับที่ (Rank)" แทน

### 5. ด้านการทำ Reranking
* **ต่างกันตรงไหน:** ระบบที่ (2) เพิ่มขั้นตอน Reranking ด้วยโมเดล **Cross-Encoder (`bge-reranker-v2-m3`)** คั่นกลางก่อนส่งให้ LLM
* **ดีขึ้นอย่างไร:** คัดกรองเฉพาะ Chunk ที่เกี่ยวข้องกับคำถามจริงๆ ได้ลึกซึ้งและแม่นยำกว่า Embedding ปกติ
* **เพราะเหตุใด:** Cross-Encoder นำทั้ง Query และ Chunk เข้าสู่กลไก Self-Attention พร้อมกันระดับคำต่อคำ ทำให้วัดความเกี่ยวข้อง (Relevance) ได้แม่นยำตรงตามข้อจำกัดของ Generic RAG
